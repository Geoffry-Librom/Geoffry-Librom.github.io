在日常团队聚餐、机务班组订餐或部门工会活动中，经常会遇到"每个人消费金额不同"的微信群收款场景。当人数达到几十人时，在手机上挨个搜索人名、核对账单、输入带小数点的金额，不仅耗时费力，还极易看错串行。

借助 **macOS Sequoia + iOS 18 的「iPhone 镜像 (iPhone Mirroring)」** 功能，我们可以将手机画面投射到 Mac 屏幕上，并结合 **Python 计算机视觉（EasyOCR + OpenCV）与键鼠控制（PyAutoGUI）**，打造一个具备"闭环视觉校验"的全自动群收款金额分配机器人。

---

## 一、整体设计思路与状态机闭环

在跨端投屏场景下，传统的"固定坐标盲点"极不可靠（窗口拖动、网络卡顿、系统弹窗都会导致脚本崩盘）。因此，本项目采用 **OOP（面向对象）+ 视觉状态机闭环** 的设计思路：

1. **底层防抢焦与权限自检**：通过 `ctypes` 调用 macOS 原生 `AppKit` 接口，将 Python 进程设为纯后台 `Accessory` 模式，消灭脚本运行时 Dock 栏跳出"Python 小火箭"抢夺投屏窗口焦点的问题。
2. **动态锁窗与 Retina 坐标映射**：全屏寻找微信顶部的标题栏（英文版 `Specific Amount` 或中文版 `指定金额`），根据标题像素宽度自适应推算整部 iPhone 投屏窗口的边界（ROI），并自动计算 macOS Retina 屏幕的 **物理像素 vs 逻辑坐标缩放比（2.0x）**。
3. **单人 5 步闭环流水线**：
   - **Step 1（定位搜索框）**：将目标姓名写入系统剪贴板，点击搜索框唤出 iOS 原生黑色的 **`Paste`（粘贴）气泡**。
   - **Step 2（两段式粘贴与防假阳性校验）**：点击黑色 `Paste` 气泡 → 自动识别并放行 iOS 的 **`Allow Paste`（允许粘贴）弹窗**（严格避开上方的 `Don't Allow Paste`）→ 在搜索框正下方的**第一行结果区**校验是否刷出微信绿色高亮（`#07C160`）的目标姓名。
   - **Step 3（同行水平对齐点选）**：以锁定的绿色姓名为垂直基准线，在同一水平行（Y 轴偏差范围内）右侧定位 `0.00` 输入框并点击，唤出底部数字软键盘。
   - **Step 4（物理键盘极速输入 + 软键盘网格兜底）**：直接通过 Mac 物理键盘键入金额；同时对同行右侧区域做二次 OCR 校验，若仍为 `0.00` 则自动切换至屏幕软键盘网格点击兜底。
   - **Step 5（一键重置返回）**：识别并点击搜索框最右侧的灰色 `⊗` 清除按钮，清空搜索词返回初始列表，进入下一人的循环。

```bash
pip install mss numpy opencv-python pyautogui pyperclip easyocr torch torchvision
```

## 三、核心技术难点与避坑指南

### 1. 为什么 `pyautogui.click()` 坐标明明算对了，却点到了窗口外面？

- **原因**：MacBook 采用 Retina 屏幕，其**物理像素分辨率**（如 `2880×1800`）是 **PyAutoGUI 逻辑坐标**（如 `1440×900`）的 **2 倍**。而 `mss` 字典中的 `monitor['width']` 返回的也是逻辑尺寸，若用它除以 `pyautogui.size()` 会得到错误的 `1.0` 缩放比。
- **解决方案**：先抓取一帧真实图像 `sample_img`，用图像矩阵的真实列数 `sample_img.shape[1] / pyautogui.size()[0]` 计算缩放比（实测为 `2.00`），所有点击坐标转换时除以该缩放比。

### 2. 为什么 iPhone 镜像经常"吞掉"鼠标点击？

- **原因**：iPhone 镜像需要把 Mac 的鼠标点击转译为 iOS 的手指触控。如果鼠标 0ms 瞬移过去并瞬间完成按下与抬起，投屏层只会更新光标悬停位置而丢弃点击。
- **解决方案**：封装 `iphone_tap()` 方法，严格执行 **"0.10s 平滑移动到位 → 悬停 0.05s 让投屏捕获焦点 → 按下左键保持 0.08s → 抬起左键"** 的拟真触控时序。

### 3. 如何解决未过滤列表导致的"假阳性"验证？

- **原因**：假如要搜索"张三"，而初始列表第 7 行恰好本来就显示着"张三"，全屏 OCR 会直接把第 7 行误判为搜索成功，随后在步骤 3 点错行。
- **解决方案**：双重锁定——① 检查搜索框内是否还残留灰色的"搜索"占位符；② 仅在**搜索框正下方第一行区域（`sy + 40` 至 `sy + 230`）**内寻找目标姓名，并配合 OpenCV HSV 色彩空间检测**微信特有的搜索高亮绿（`#07C160`）**。

## 四、类与函数模块化设计详解

整个脚本封装在 `WeChatSplitBot` 类中：

**系统级初始化层**

- `suppress_python_dock_rocket()`：拦截 Python 启动时的 macOS Dock 图标跳动，防止焦点从 `iPhone Mirroring` 被抢走。
- `check_macos_accessibility()`：启动时自动检查当前 IDE/终端是否已开启 macOS「辅助功能」权限。

**视觉感知与坐标转换层**

- `locate_iphone_window()`：全屏寻找标题栏，动态框定手机屏幕 ROI 区域，并标定搜索框与右侧 `⊗` 按钮的基准坐标。
- `roi_point_to_screen_logic()`：将手机局部 ROI 内的物理像素坐标一键换算为全局屏幕逻辑坐标。
- `save_debug_img()`：可视化 Debug。把每一步的 **OCR 绿框、黄色同行水平基准线、红黄双圈点击靶心** 输出到 `debug_logs/` 文件夹，哪一步点偏一目了然。

**业务状态机层**

- `_detect_paste_bubble()` & `_handle_allow_paste_Popup()`：应对 iOS 粘贴气泡与系统粘贴权限弹窗，自动排除 `Don't Allow Paste` 干扰。
- `step1_and_2_search_and_paste()`：搜索框点击、粘贴、授权与第一行绿色高亮姓名核验。
- `step3_click_amount_box()`：根据步骤 2 锁定的姓名 Y 坐标，截取同行条带区域识别右侧的 `0.00` 或 `CNY`，实现同行精准点击。
- `step4_input_amount()`：优先用 Mac 物理键盘高速输入金额，内置 `_fallback_tap_screen_keypad()` 软键盘网格点击作为双保险。
- `step5_clear_search()`：识别搜索框右侧灰色的 `⊗` 图标并点击重置。

## 六、常见问题与实用技巧（FAQ）

1. **如何关掉 iOS 每次弹出的 `Allow Paste` 询问框？**
   脚本已经内置了 `_handle_allow_paste_Popup()` 自动点掉弹窗。如果希望每人再快 1 秒，可以在 iPhone 上打开 **「设置 → App → 微信 → 从其他 App 粘贴」**，把"询问"改为 **"允许"**。

2. **重新运行脚本前需要注意什么？**
   微信群收款输入框是"追加输入"：如果某人原本已填了 `54.3`，再次运行脚本点进去输入 `54.3` 会变成 `54354.3`。中途中断需要重跑时，请先点微信页面左下角的 **`Reset`（重置）** 把所有人清零回 `0.00`。

3. **遇到生僻字或账单姓名打错字怎么办？**
   当某个人名连续 3 次未检索出绿色高亮结果时，脚本会自动点 `⊗` 清空搜索框并跳过该人，继续完成后续所有人的录入，最后在控制台打印未匹配成功的名单供人工核对。
